# Architecture Decision Records

ADR ghi lại các quyết định kiến trúc quan trọng và trade-off.

## Trạng thái

- Proposed.
- Accepted.
- Superseded.
- Deprecated.
- Rejected.

## Quy tắc

- Không xóa ADR đã Accepted.
- Khi thay đổi quyết định, tạo ADR mới và đánh dấu ADR cũ là Superseded.
- ADR phải liên kết tới issue hoặc pull request khi có thể.

## ADR baseline cần tạo

- ADR-001 Flutter for mobile.
- ADR-002 Next.js for web administration.
- ADR-003 NestJS application backend.
- ADR-004 Supabase/PostgreSQL managed data platform.
- ADR-005 Shared-schema multi-tenancy.
- ADR-006 PostgreSQL RLS as defense in depth.
- ADR-007 Offline-first local SQLite.
- ADR-008 Revision-based delta synchronization.
- ADR-009 Realtime as notification only.
- ADR-010 Price books and immutable price history.
- ADR-011 Inventory ledger.
- ADR-012 Idempotent transactional commands.
- ADR-013 Modular monolith.
- ADR-014 Docker for local backend and CI.
- ADR-015 Managed production infrastructure initially.
- ADR-016 AI with human-in-the-loop.
